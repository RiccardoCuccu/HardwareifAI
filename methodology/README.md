# Methodology

How the curriculum itself gets designed: the process, criteria, and validation rules behind every topic, paper, and project decision.

## Contents

One overview page defines the process and the concepts that cut across it; the other three define how each individual task is actually carried out, split by how often that task runs.

1. [`curriculum_design_process.md`](curriculum_design_process.md) - the end-to-end process overview: why the process starts from engineering problems rather than a syllabus, the full step list organised by cadence, and the transversal concepts every cadence draws on (the topic selection framework and its fundamental-vs-fad rubric, the validation channels, the evaluation metrics, and the continuous-update mechanics that keep the curriculum current indefinitely).
2. [`one_time_methodology.md`](one_time_methodology.md) - the tasks performed once, at course creation: professional profile definition, the dependency graph's seed chain, and toolchain selection.
3. [`quarterly_methodology.md`](quarterly_methodology.md) - the tasks repeated every quarter, in the same sitting: the market analysis refresh, portfolio and graph validation, and the Technology Radar review.
4. [`per_module_methodology.md`](per_module_methodology.md) - the tasks repeated for every new module: taxonomy population, core principles mapping, paper analysis, dependency graph slotting, learning outcomes definition, module design, project design, and per-module validation.

Read the overview first: it explains what each task is for and where it sits in the pipeline, then links into whichever cadence page defines how to perform it.
